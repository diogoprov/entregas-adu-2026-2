# Entregas — Análise de Dados Univariados (PPGBA/UFMS, 2026/2)

Este repositório é **privado**. Só quem está na disciplina enxerga.

## Como entregar

1. Compacte num único `.zip`: o `.qmd`, o `.html` renderizado e os dados
   (ou um `README` curto dizendo de onde baixá-los).
2. Abra **Issues → New issue → Entrega do trabalho final**.
3. Preencha o formulário e arraste o `.zip` para o campo *Arquivos*.

Pronto. Não mande por e-mail.

## Como funciona a revisão

Eu respondo na própria issue. Se o comentário for sobre um trecho
específico, cito o código no comentário. Você responde ali mesmo — não
abra issue nova. Quando revisar, troco a etiqueta de `recebida` para
`revisada`.

Para reenviar depois de corrigir: anexe o `.zip` novo **na mesma issue**,
num comentário. O histórico de versões fica visível, o que é bom para
você e para mim.

## Isto é aberto para a turma

Todo mundo vê todas as entregas e todos os comentários. É deliberado:
metade do que se aprende em análise de dados vem de ver a decisão que
outra pessoa tomou num problema parecido, e o erro que alguém já cometeu
custa mais barato quando é comentado em público.

Duas consequências práticas:

- **A nota não vem por aqui.** Só o feedback técnico.
- Se os seus dados não podem circular — embargo, terceiros, questão
  ética —, não anexe o arquivo: mande o `.qmd` e o `.html` e descreva os
  dados. Fale comigo antes se tiver dúvida.

## Prazo

A combinar com a turma no Encontro 1.

## O que é avaliado

Os critérios estão na [página do trabalho
final](https://provetelab.org/analise-dados-univariados-2026-2/trabalho-final.html).
O resumo: o modelo corresponde ao que os dados são e a como foram
coletados; os problemas foram procurados e discutidos, não escondidos;
cada escolha tem uma razão explícita; o documento renderiza em outra
máquina; os resultados são traduzidos para biologia sem exagero; as
limitações estão declaradas.

Um modelo que não ajustou bem, com diagnóstico honesto, vale mais do que
um modelo aparentemente perfeito com o diagnóstico omitido.
